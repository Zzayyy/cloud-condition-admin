# 验证脚本

本目录是**交付验证工具**（不是运行时依赖），用来证明后端与 SQL 的正确性、以及
「没有动到 `qianlong_cloud` 库里已有的任何表」。

## 前置

```bash
pip install pymysql bcrypt      # 见 requirements.txt
```

后端需先启动（跑接口类脚本时）：

```bash
cd .. && mvn spring-boot:run     # 监听 127.0.0.1:8000，上下文 /api
```

## 一键全跑

```bash
python run_all_tests.py
```

它会在**每个套件前重灌测试数据**，然后依次跑下面三个套件。
重灌是必须的：这些测试会真的改数据（解锁账号、改密码、写审计、建账号），
不重灌时后一个套件的失败往往源自前一个套件的副作用，属于**测试污染**而非产品缺陷，
会把人误导到错误的方向上排查。

## 各脚本说明

| 脚本 | 作用 | 需要后端 |
|---|---|---|
| `gen_sql.py` | **生成** `../sql/` 下的三个 SQL 文件（DDL + 测试数据） | 否 |
| `apply_sql.py` | 执行 SQL 文件到数据库；`schema` 建表灌数据，`drop` 回滚 | 否 |
| `audit_sql.py` | **静态审计**：逐条语句证明脚本碰不到 `T_Admin*` 以外的表 | 否 |
| `make_baseline.py` | 生成既有业务表的结构基线快照（只读） | 否 |
| `verify_untouched.py` | 核对既有表的结构/索引/视图/行数未被改动 | 否 |
| `e2e_test.py` | 接口端到端：行为 + 错误分支（175 项） | 是 |
| `contract_test.py` | 前后端契约：字段名与类型逐一对齐（148 项） | 是 |
| `page_sim_test.py` | 三个页面的行为重放：返回的数据够不够渲染（81 项） | 是 |
| `proxy_test.py` | 经 Vite 代理的完整链路联调（需另起 `vite --port 5199`） | 是 + Vite |
| `paths.py` | 位置无关的路径解析（脚本挪目录也不会失效） | — |

## 两层「没动别的表」证据

行数核对只是**事后**验证，只能证明「这次没被改」。
静态审计证明的是「脚本本身的结构不允许它改别的表」——
即使将来有人在别的环境、别的时机执行，结论依然成立。

```bash
python audit_sql.py          # 语法层面：只可能触及 T_Admin*
python verify_untouched.py   # 执行之后：既有表的结构与内容都没变
```

`audit_sql.py` 会先剥掉注释与字符串字面量，只留下**真正可执行的语句**再扫描。
这一步是必要的：脚本里刻意在注释中点名了既有表（说明「不要动它们」），
不剥掉就会把这些说明文字误判成「脚本碰了别的表」。

## 修改 SQL 后请重新生成基线

`verify_untouched.py` 依赖 `baseline_schema.json`。若现场真的合法变更了既有表结构
（例如 DBA 加了索引），需要重新生成基线，否则会一直报不一致：

```bash
python make_baseline.py      # 只读，仅查 information_schema 与 SHOW CREATE
```

> ⚠️ 重新生成基线会**掩盖**真实的越界改动。只有在确认变更是有人有意为之之后才做。
